## Install

You can use our AI-Assisted Setup to install the plugin. Add the Capgo skills to your AI tool using the following command:

```bash
npx skills add https://github.com/Cap-go/capgo-skills --skill capacitor-plugins
```

Then use the following prompt:

```text
Use the `capacitor-plugins` skill from `Cap-go/capgo-skills` to install the `@capgo/capacitor-age-range` plugin in my project.
```

If you prefer Manual Setup, install the plugin by running the following commands and follow the platform-specific instructions below:

```bash
npm install @capgo/capacitor-age-range
npx cap sync
```

## Android setup

The plugin uses the [Google Play Age Signals API](https://developer.android.com/google/play/age-signals/). The native dependency defaults to `com.google.android.play:age-signals:0.0.6`. Google Play requires age-signals `0.0.4+` from **January 2027** in mandatory-sharing regions, so the plugin ships `0.0.6` by default.

**Minimum supported version is `0.0.4`.** The plugin is built and unit tested in CI against both `0.0.4` and `0.0.6`. Play Age Signals `0.0.2` and `0.0.3` are **not supported** (they lack the types the plugin maps result fields from).

Override the library version in your app's `android/variables.gradle` (any value from `0.0.4` up):

```gradle
ext {
    androidPlayAgeSignalsVersion = '0.0.6'
}
```

By default, `requestAgeRange()` calls `checkAgeSignals()` only (`androidAgeSignalsAccess: 'never'`), which does not show Google's in-app sharing prompt. For mandatory-sharing regions or when you want the Play Store sharing UI, set `androidAgeSignalsAccess` to `'always'` or `'whenMandatory'`. See [Request age signals](https://developer.android.com/google/play/age-signals/request-age-signals/).

### Access modes (`androidAgeSignalsAccess`)

| Value | Behavior |
| --- | --- |
| `never` (default) | Calls `checkAgeSignals()` only. No in-app sharing prompt. |
| `always` | Always calls `requestAgeSignalsAccess()` first (Google may show the sharing prompt when applicable). Calls `checkAgeSignals()` when access is `SHARED`; otherwise returns the access status (see the mapping below). |
| `whenMandatory` | Applied at runtime on Play Age Signals `0.0.6+`: the plugin calls `getApplicableAgeFeatures()` and requests access only when it reports `MANDATORY_SHARING`. On `0.0.4` to `0.0.5` (where that method does not exist), or if the probe fails, it falls back to `checkAgeSignals()` only. |

Unknown `androidAgeSignalsAccess` values are logged on Android and treated as `never`.

### R8 / ProGuard

`whenMandatory` reaches the `0.0.6` APIs through reflection. The plugin AAR ships `consumer-rules.pro` keep rules for `ApplicableAgeFeaturesRequest` and `ApplicableAgeFeature`, so minified release builds keep working with no extra setup. If those rules are stripped, `whenMandatory` falls back to `checkAgeSignals()` only.

Requirements: Android API 24+ (minSdk) and an up-to-date Google Play Store.

## Quick start

```typescript
import { AgeRange } from '@capgo/capacitor-age-range';

const result = await AgeRange.requestAgeRange({ ageGates: [13, 16, 18] });
```

Request sharing access before checking signals when your app runs in a mandatory-sharing region:

```typescript
const result = await AgeRange.requestAgeRange({
  ageGates: [13, 16, 18],
  androidAgeSignalsAccess: 'whenMandatory',
});
```

## Common pitfalls

- **Not ID proof**: signals aid compliance UX, not government ID.
- **Unknown status**: design defaults for older OS versions.
- **Disclosures**: document usage in privacy policies.

## API Overview

### `requestAgeRange`

Request the user's age range.

On Android: queries Google Play Age Signals API. By default no in-app prompt is shown; set `androidAgeSignalsAccess` to request sharing access when needed.
On iOS: presents the system DeclaredAgeRange dialog (requires iOS 26.2+).

```typescript
import { AgeRange } from '@capgo/capacitor-age-range';

const result = await AgeRange.requestAgeRange({ ageGates: [13, 16, 18] });
if (result.status === 'SHARING') {
  console.log('Age range:', result.ageLower, '-', result.ageUpper);
}
```

## Type Reference

### `RequestAgeRangeOptions`
Options for the age range request.
```typescript
export interface RequestAgeRangeOptions {
  /**
   * Age thresholds for the request.
   *
   * On iOS: these are passed to `requestAgeRange(ageGates:)` as the
   * age boundaries presented in the system dialog. Common values: [13, 16, 18].
   *
   * On Android: this parameter is ignored (Play Age Signals returns
   * predefined ranges: 0-12, 13-15, 16-17, 18+).
   *
   * @default [13, 16, 18]
   * @since 8.0.0
   */
  ageGates?: number[];

  /**
   * Android-only. Whether to call `requestAgeSignalsAccess()` before `checkAgeSignals()`.
   *
   * - `never` (default): calls `checkAgeSignals()` only, matching pre-0.0.4 behavior with no in-app sharing prompt.
   * - `always`: always requests access first (Google may show the sharing prompt when applicable).
   * - `whenMandatory`: requests access only when `getApplicableAgeFeatures()` reports `MANDATORY_SHARING` (Play Age Signals 0.0.6+ at runtime; on 0.0.4 to 0.0.5 or failure falls back to `checkAgeSignals()` only).
   *
   * Unknown values are logged on Android and treated as `never`.
   *
   * @default 'never'
   * @since 8.3.0
   */
  androidAgeSignalsAccess?: AndroidAgeSignalsAccessMode;
}
```

### `AgeRangeResult`
Result of the age range request.
```typescript
export interface AgeRangeResult {
  /**
   * The outcome status of the age range request.
   *
   * @since 8.0.0
   */
  status: AgeRangeStatus;

  /**
   * Inclusive lower bound of the user's age range.
   *
   * Present when age data is available.
   *
   * @since 8.0.0
   */
  ageLower?: number;

  /**
   * Inclusive upper bound of the user's age range.
   *
   * May be absent if the user is in the highest age bracket (e.g. 18+).
   *
   * @since 8.0.0
   */
  ageUpper?: number;

  /**
   * How the age was declared/determined.
   *
   * On iOS: 'SELF_DECLARED' or 'GUARDIAN_DECLARED'.
   * On Android: derived from `ageRangeSource` (TIER_A self-declared, TIER_B guardian-managed, TIER_C/TIER_D verified).
   *
   * @since 8.0.0
   */
  declarationSource?: DeclarationSource;

  /**
   * Android-only. Legacy mapping from Play Age Signals 0.0.2 `userStatus()`.
   *
   * Play Age Signals 0.0.4+ removed this field. The plugin derives approximate values from
   * `ageRangeSource` and `significantChangeStatus` for backward compatibility. Prefer those fields.
   *
   * @deprecated since 8.3.0. Use `ageRangeSource` and `significantChangeStatus` instead.
   * @since 8.0.0
   */
  androidUserStatus?: AndroidUserStatus;

  /**
   * Android-only. How Google classified the shared age range (Play Age Signals 0.0.4+).
   *
   * @since 8.3.0
   */
  ageRangeSource?: AndroidAgeRangeSource;

  /**
   * Android-only. Approval status for significant account changes in applicable jurisdictions.
   *
   * @since 8.3.0
   */
  significantChangeStatus?: AndroidSignificantChangeStatus;

  /**
   * Android-only. Effective date of the most recently approved significant change.
   *
   * @since 8.3.0
   */
  significantChangeApprovalDate?: string;

  /**
   * Android-only. Alias for `significantChangeApprovalDate` (Play 0.0.2 field name).
   *
   * @deprecated since 8.3.0. Use `significantChangeApprovalDate`.
   * @since 8.0.0
   */
  mostRecentApprovalDate?: string;

  /**
   * Android-only. Result of `requestAgeSignalsAccess()` when `androidAgeSignalsAccess` is not `never`.
   *
   * @since 8.3.0
   */
  androidAgeSignalsAccessStatus?: AndroidAgeSignalsAccessStatus;

  /**
   * Android-only. Install identifier for supervised installs in Google Play.
   *
   * @since 8.0.0
   */
  installId?: string;
}
```

### `AgeRangeStatus`
Top-level status of the age range request.
```typescript
export type AgeRangeStatus =
  /**
   * The user shared their age range (iOS) or age signals are available (Android).
   */
  | 'SHARING'
  /**
   * The user declined to share their age range.
   */
  | 'DECLINED_SHARING'
  /**
   * The age range API is not available on this device/OS version.
   */
  | 'NOT_AVAILABLE'
  /**
   * An error occurred while requesting the age range.
   */
  | 'ERROR';
```

### `DeclarationSource`
How the age range was declared or determined.
```typescript
export type DeclarationSource =
  /** The user self-declared their age (iOS). */
  | 'SELF_DECLARED'
  /** A guardian declared the user's age (iOS Family Sharing or Android supervised). */
  | 'GUARDIAN_DECLARED'
  /** Google has verified the user is 18+ (Android only). */
  | 'VERIFIED'
  /** Source is unknown or not provided by the platform. */
  | 'UNKNOWN';
```

### `AndroidUserStatus`

```typescript
/**
 * @deprecated since 8.3.0. Mapped from `ageRangeSource` / `significantChangeStatus` on Play Age Signals 0.0.4+.

export type AndroidUserStatus =
  | 'VERIFIED'
  | 'SUPERVISED'
  | 'SUPERVISED_APPROVAL_PENDING'
  | 'SUPERVISED_APPROVAL_DENIED'
  | 'UNKNOWN'
  | 'EMPTY';
```

Android-only. Controls the Play Age Signals access request flow.

export type AndroidAgeSignalsAccessMode = 'never' | 'always' | 'whenMandatory';

Android-only. Play Age Signals access status from `requestAgeSignalsAccess()`.

export type AndroidAgeSignalsAccessStatus =

## Android response mapping (Play Age Signals 0.0.4+)

| `ageRangeSource` | `significantChangeStatus` | `status` | `declarationSource` | deprecated `androidUserStatus` |
| --- | --- | --- | --- | --- |
| TIER_D / TIER_C | (any) | SHARING | VERIFIED | VERIFIED |
| TIER_B | PENDING | SHARING | GUARDIAN_DECLARED | SUPERVISED_APPROVAL_PENDING |
| TIER_B | DECLINED | SHARING | GUARDIAN_DECLARED | SUPERVISED_APPROVAL_DENIED |
| TIER_B | other / null | SHARING | GUARDIAN_DECLARED | SUPERVISED |
| TIER_A | (any) | SHARING | SELF_DECLARED | UNKNOWN |
| null / UNSPECIFIED | - | DECLINED_SHARING | - | UNKNOWN |

When `androidAgeSignalsAccess` is not `never`, `requestAgeSignalsAccess()` may return `NOT_SHARED` (`DECLINED_SHARING`) or `VERIFICATION_REQUIRED` (`NOT_AVAILABLE` plus `androidAgeSignalsAccessStatus`).
