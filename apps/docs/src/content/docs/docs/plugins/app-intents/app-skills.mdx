Apple documents app skills under [Orchestrating complex actions with app skills](https://developer.apple.com/documentation/appintents/orchestrating-complex-actions-with-app-skills/). The feature ships in the **iOS 27.3 Developer Preview** and needs Apple Intelligence on a **physical device** for skills verification. Simulator is not enough for the full skills evaluation loop.

This guide matches the implementation in [`@capgo/capacitor-app-intents` plugin PR #2](https://github.com/Cap-go/capacitor-app-intents/pull/2).

## What you get

- **Multi step skills**: Siri can follow a skill body that orchestrates several tool intents in one request.
- **Typed intents**: `generate-typed-intents.mjs` emits Swift with parameters, entities, and string results for chaining.
- **Real results to Siri**: `awaitJavaScriptResult` intents wait for JavaScript and surface `value` / `message` to Siri via `completeInvocation()` or `withInvocationCompletion`.
- **Generic path unchanged**: `CapgoDispatchAppIntent` and phrase codegen from `generate-app-shortcuts.mjs` still work for simple shortcuts.

## Install

Install or upgrade the plugin, then sync iOS:

```bash
bun add @capgo/capacitor-app-intents
bunx cap sync ios
```

Use a build of the plugin that includes the Siri app skills work (see the [plugin PR](https://github.com/Cap-go/capacitor-app-intents/pull/2)) until it is released on npm.

## Codegen config

<Steps>

1. Copy `app-intents.codegen.example.json` from the plugin package to `app-intents.codegen.json` in your app repo.
2. Define `shortcuts`, `intents`, and `skills`. Each intent can set `tool`, `awaitJavaScriptResult`, `foregroundOnly`, `execution`, and `parameters`. Each skill has `name`, `description`, and markdown `body` that references your tools.
3. Keep `actionName` aligned with your JavaScript handler and with `shortcuts[].intent` when you use typed intents.

</Steps>

Example intent flags (from the plugin example config):

- `tool: true` marks a `ToolIntent` (requires iOS 27.3 SDK when you enable the trait in generated Swift).
- `awaitJavaScriptResult: true` sets `awaitingResult` on the bridge invocation so Siri waits for JavaScript.
- `foregroundOnly: true` asks the system to bring your app forward before running the tool.
- `execution: "javascript"` runs through `CapgoIntentPerformExecutor`; use `"native"` to prefer `CapgoNativeIntentHandlerRegistry`.

## Generate typed intents

```bash
node node_modules/@capgo/capacitor-app-intents/scripts/generate-typed-intents.mjs \
  --config app-intents.codegen.json \
  --output-dir ios/App/App/GeneratedAppIntents
```

Add every generated `.swift` file to your iOS **app** target (not the Capacitor plugin SPM product). Link the plugin package on the app target so `CapgoIntentPerformExecutor` and `CapgoCatalogEntity` resolve.

Generated intents compile on iOS 16+ without the `@AppIntent(.tool)` trait. Uncomment or add `@AppIntent(.tool)` in app owned generated Swift when your Xcode SDK supports it.

## Generate Skills.skillsbundle

Skills bundle content comes from the `skills` array in the same codegen JSON. The generator writes a folder you rename or copy to `Skills.skillsbundle`:

```bash
node node_modules/@capgo/capacitor-app-intents/scripts/generate-skills-bundle.mjs \
  --config app-intents.codegen.json \
  --output ios/App/App/Skills.skillsbundle
```

In Xcode:

1. Drag `Skills.skillsbundle` into the app target.
2. Confirm it appears under **Copy Bundle Resources** for the app target.

After install, verify `Skills.skillsc` exists under `MyApp.app/Metadata.appintents/` on device.

## JavaScript completion for Siri

Register your listener with `withInvocationCompletion` so awaiting invocations call `completeInvocation` or `failInvocation` for you:

```typescript
import {
  CapgoAppIntents,
  useAppIntentsListener,
  withInvocationCompletion,
  isAwaitingResult,
} from '@capgo/capacitor-app-intents';

await useAppIntentsListener(
  withInvocationCompletion(async (invocation) => {
    if (invocation.name === 'orderDish') {
      return { value: 'Ordered pasta', message: 'Your pasta order is in.' };
    }
  }),
);
```

Manual control:

```typescript
await CapgoAppIntents.completeInvocation({
  id: invocation.id,
  result: { value: 'Done', message: 'Finished in your app.' },
});

await CapgoAppIntents.failInvocation({
  id: invocation.id,
  error: 'Could not complete the order.',
});
```

Use `isAwaitingResult(invocation)` when you branch between fire and forget handlers and tool results.

## Native handlers

When JavaScript is not ready or you want zero webview work, register a native handler early (for example in `AppDelegate`):

```swift
CapgoNativeIntentHandlerRegistry.shared.register(actionName: "pingNative") { _ in
    return ["value": "pong", "message": "Handled in Swift"]
}
```

Set `execution: "native"` on the generated intent. Native results use the same `value` / `message` keys Siri expects for chaining.

## Entity catalogs and on screen context

Publish catalogs from JavaScript so Siri can resolve entity parameters:

```typescript
await CapgoAppIntents.setEntityCatalog({
  type: 'dish',
  entries: [{ id: 'pasta', title: 'Pasta' }],
});
```

`CapgoCatalogEntityQuery` serves `suggestedEntities()` from the catalog. When your UI is web only and cannot adopt SwiftUI `appEntityIdentifier` yet, hint what is on screen:

```typescript
await CapgoAppIntents.setOnscreenEntityContext({
  entities: [{ catalogType: 'dish', entityId: 'pasta', title: 'Pasta' }],
});

await CapgoAppIntents.clearOnscreenEntityContext();
```

<Aside type="note">
Full on screen awareness (`appEntityIdentifier`, `AppEntityUIElementsContext`) is documented by Apple but not wrapped by this plugin yet. Use `setOnscreenEntityContext` as the bridge for Capacitor web UIs.
</Aside>

## Test on a real device

<Steps>

1. Build and run on an Apple Intelligence capable device on **iOS 27.3** beta. Use a development build or TestFlight internal build.
2. Open the app once in the foreground so bundles and catalogs initialize.
3. Speak phrases from each skill `description`, then rephrase them naturally.
4. Run a tool intent with `awaitJavaScriptResult: true` and confirm Siri speaks your JavaScript `value` or `message`.
5. Trigger a skill whose body chains two tools in one Siri request.
6. Optionally run Apple's [SiriEvaluations](https://developer.apple.com/documentation/SiriEvaluations) suite against your build.

</Steps>

## Guarded APIs and CI

<Aside type="caution">
`ToolIntent` and `@AppIntent(.tool)` are not declared in the plugin Swift package so CI keeps building on current Xcode. Add the tool trait only in app owned generated Swift when your SDK supports iOS 27.3.
</Aside>

- **SDK**: Typed tool intents and skills bundle metadata expect the iOS 27.3 SDK (Xcode 27.3 beta).
- **Siri chaining without tools**: `completeInvocation()` / `failInvocation()` also apply to typed codegen on iOS 17+ for string results; the generic `CapgoDispatchAppIntent` path still does not return spoken strings on iOS 16.
- **Simulator**: Fine for shortcut dispatch and JavaScript handlers; not for full app skills evaluation per Apple preview guidance.
