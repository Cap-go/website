## Install

You can use our AI-Assisted Setup to install the plugin. Add the Capgo skills to your AI tool using the following command:

```bash
npx skills add https://github.com/Cap-go/capgo-skills --skill capacitor-plugins
```

Then use the following prompt:

```text
Use the `capacitor-plugins` skill from `Cap-go/capgo-skills` to install the `@capgo/capacitor-downloader` plugin in my project.
```

If you prefer Manual Setup, install the plugin by running the following commands and follow the platform-specific instructions below:

```bash
bun add @capgo/capacitor-downloader
bunx cap sync
```

## Quick start

Download to a known folder, listen for progress, and resume after app restarts when supported.

```typescript
import { CapacitorDownloader } from '@capgo/capacitor-downloader';

const progressListener = await CapacitorDownloader.addListener('downloadProgress', (event) => {
  if (event.id === 'offline-pack') {
    console.log(event.progress);
  }
});

const task = await CapacitorDownloader.download({
  id: 'offline-pack',
  url: 'https://cdn.example.com/large-pack.zip',
  destination: 'downloads/offline-pack.zip',
});
```

## Example: completion notification

When the app may be in the background, set `downloadCompletedNotificationText` to alert the user after a successful download. The plugin shows a system notification only when notification permission is granted. The plugin manifest already merges `POST_NOTIFICATIONS` on Android, so on Android 13 and later your app only needs to request it at runtime; on iOS request notification authorization before the download finishes. Tapping the notification reopens the app. On Android, the completion alert is still posted while your app is in the foreground. On iOS, a notification that arrives in the foreground is shown only if your app's `UNUserNotificationCenter` delegate presents it, so without a notifications plugin it is usually silent and `downloadCompleted` events are the reliable signal there.

```typescript
import { CapacitorDownloader } from '@capgo/capacitor-downloader';

await CapacitorDownloader.download({
  id: 'offline-pack',
  url: 'https://cdn.example.com/large-pack.zip',
  destination: 'downloads/offline-pack.zip',
  downloadCompletedNotificationText: 'Your pack is ready',
  notification: 'hidden', // Android: rely on plugin events and the completion alert
});
```

On Android, pair `notification: 'hidden'` with `downloadCompletedNotificationText` when you do not want DownloadManager progress notifications but still want a completion alert. If Android ends the app process before the download completes, the completion alert is not shown, and `hidden` also suppresses the DownloadManager completion notification.

## Example: inspect finished file

```typescript
import { Capacitor } from '@capacitor/core';
import { Directory, Filesystem } from '@capacitor/filesystem';

const relativePath = 'downloads/offline-pack.zip';
const path =
  Capacitor.getPlatform() === 'ios'
    ? (await Filesystem.getUri({ directory: Directory.Documents, path: relativePath })).uri
    : relativePath;

const info = await CapacitorDownloader.getFileInfo({ path });
```

## Android OkHttp engine

This option ships in the next plugin release, which is not published yet. It is tracked in [capacitor-downloader PR #105](https://github.com/Cap-go/capacitor-downloader/pull/105). Until that version is published, installing `@capgo/capacitor-downloader` from npm does not include `androidHttpEngine`. After that release, Android can use an opt-in **OkHttp** stack for app-private destinations. With `androidHttpEngine: 'auto'`, **DownloadManager** is used for `public-downloads/...` and for other relative paths under app external files. If app external files storage is unavailable, those other relative paths fall back to app-private internal storage and `auto` selects OkHttp. `'okhttp'` rejects `public-downloads/...` paths.

### Choose `androidHttpEngine`

| Value | When to use |
| ----- | ----------- |
| `'auto'` (default) | OkHttp for `cache/...`, `files/...`, and absolute paths under internal cache/data/files; DownloadManager for other relative paths and `public-downloads/...`. If app external files storage is unavailable, other relative paths fall back to internal files storage and `auto` selects OkHttp. |
| `'okhttp'` | Force OkHttp for app-private and internal destinations (sensitive offline packs, internal-only files). Requests to `public-downloads/...` are rejected. Transfers run in the app process and do not continue after the process is killed. |
| `'downloadManager'` | Force system DownloadManager (same as pre-8.4 default behavior for external paths). Requests that target `files/...`, `cache/...`, or another app-private path under cache, data, or files are rejected. |

### Android `destination` prefixes

| Prefix | Resolves to | `auto` engine |
| ------ | ----------- | ------------- |
| `cache/...` | App cache directory | OkHttp |
| `files/...` | App-private files directory | OkHttp |
| `public-downloads/...` | Public Downloads folder | DownloadManager (`'okhttp'` rejects this prefix) |
| Other relative paths | App external files directory (default). If that storage is unavailable, app-private internal files. | DownloadManager, or OkHttp when the internal fallback is used |

### Example: private offline pack

```typescript
import { CapacitorDownloader } from '@capgo/capacitor-downloader';

const progress = await CapacitorDownloader.addListener('downloadProgress', (event) => {
  if (event.id === 'offline-pack') {
    console.log(event.progress);
  }
});

await CapacitorDownloader.download({
  id: 'offline-pack',
  url: 'https://cdn.example.com/pack.zip',
  destination: 'files/offline/pack.zip',
  androidHttpEngine: 'auto',
  notification: 'hidden',
});
```

OkHttp runs inside the app process. If Android kills that process, the download does not continue the way a DownloadManager transfer does. App-private destinations (`cache/...`, `files/...`) require OkHttp, so they cannot use DownloadManager's out-of-process continuation. For `public-downloads/...` and external-files paths, keep `androidHttpEngine` at `'auto'` (or set `'downloadManager'`) when the transfer must outlive the app process. Do not set `'okhttp'` for `public-downloads/...`; that request is rejected.

### Notifications with OkHttp

- `'hidden'`: no system notification; use `downloadProgress` / `downloadCompleted` listeners (recommended for OkHttp).
- `'completed'`: no notification during transfer; one completion notification when the file finishes. On Android 13 and later, the host app must request the `POST_NOTIFICATIONS` runtime permission. If that permission is denied, the plugin skips the notification (the download still finishes, and `downloadCompleted` / `downloadFailed` still fire).
- `'progress'`: same as `'hidden'` on the OkHttp path (DownloadManager still shows progress notifications).

DownloadManager destinations continue to support `'completed'`, `'progress'`, and `'hidden'` as before.

### OkHttp limits

- At most 4 OkHttp transfers run at the same time. Additional OkHttp downloads wait until a slot is free.
- HTTP 206 Partial Content is not supported. The OkHttp path fails that response (this plugin does not resume through range requests).
- `stop()` cancels an in-flight OkHttp transfer and deletes the destination file, including when the transfer has already finished.

## Common pitfalls

- **Storage destination**: pick a `destination` your app can read on each platform. On Android, use `cache/` or `files/` prefixes for app-private OkHttp downloads.
- **Background**: downloads run on iOS and Android in the background. On Android, DownloadManager can continue after the app process is killed. OkHttp runs in the app process, so a download may stop if Android kills that process. On Web, `download()` is not implemented; use a browser download flow instead.
- **Status**: use `checkStatus` while the app process is still alive. On iOS, task IDs are not restored after relaunch.

## API Overview

### `download`

Start a new download task.

```typescript
import { CapacitorDownloader } from '@capgo/capacitor-downloader';

const task = await CapacitorDownloader.download({
  id: 'my-download',
  url: 'https://example.com/file.pdf',
  destination: 'downloads/file.pdf'
});
```

### `pause`

Pause an active download.
Download can be resumed later from the same position.

```typescript
import { CapacitorDownloader } from '@capgo/capacitor-downloader';

await CapacitorDownloader.pause({ id: 'id-123' });
```

### `resume`

Resume a paused download.
Continues from where it was paused.

```typescript
import { CapacitorDownloader } from '@capgo/capacitor-downloader';

await CapacitorDownloader.resume({ id: 'id-123' });
```

### `stop`

Stop and cancel a download permanently.
Downloaded data will be deleted, including a file that already finished on the OkHttp path.

```typescript
import { CapacitorDownloader } from '@capgo/capacitor-downloader';

await CapacitorDownloader.stop({ id: 'id-123' });
```

### `checkStatus`

Check the current status of a download.

```typescript
import { CapacitorDownloader } from '@capgo/capacitor-downloader';

const result = await CapacitorDownloader.checkStatus({ id: 'id-123' });
console.log(result);
```

### `getFileInfo`

Get information about a downloaded file.

```typescript
import { CapacitorDownloader } from '@capgo/capacitor-downloader';

const result = await CapacitorDownloader.getFileInfo({ path: 'path/to/file' });
console.log(result);
```

## Type Reference

### `DownloadOptions`
Configuration options for starting a download.
```typescript
export interface DownloadOptions {
  /** Unique identifier for this download task */
  id: string;
  /** URL of the file to download */
  url: string;
  /** Local file path where the download will be saved */
  destination: string;
  /** Optional HTTP headers to include in the request */
  headers?: { [key: string]: string };
  /** Network type requirement for download */
  network?: 'cellular' | 'wifi-only';
  /** Download priority level */
  priority?: 'high' | 'normal' | 'low';
  /**
   * Android DownloadManager notification visibility. Defaults to `completed` when omitted.
   * - `completed`: shows a notification during the download and after it completes.
   * - `progress`: shows a notification only during the download.
   * - `hidden`: shows no DownloadManager notification.
   */
  notification?: 'completed' | 'progress' | 'hidden';
  /**
   * Optional localized text for a system notification after a successful download.
   * Requires notification permission on iOS and Android.
   */
  downloadCompletedNotificationText?: string;
}
```

### `DownloadTask`
Represents the current state and progress of a download task.
```typescript
export interface DownloadTask {
  /** Unique identifier for the download task */
  id: string;
  /** Download progress from 0 to 100 */
  progress: number;
  /** Current state of the download */
  state: 'PENDING' | 'RUNNING' | 'PAUSED' | 'DONE' | 'ERROR';
}
```
