## Overview

`@capgo/capacitor-watch` connects your Capacitor phone app to a companion watch app:

- **iOS**: [WatchConnectivity](https://developer.apple.com/documentation/watchconnectivity) with a watchOS target and optional [CapgoWatchSDK](https://github.com/Cap-go/capacitor-watch).
- **Android**: [Wear OS Data Layer](https://developer.android.com/training/wearables/data/data-layer) (`play-services-wearable`) with a Wear OS module in the same Android project.
- **Web**: not supported; `getInfo()` returns safe defaults and other methods reject.

## Platform support

Capabilities below match the native implementations in [CapgoWatchPlugin.swift](https://github.com/Cap-go/capacitor-watch/blob/main/ios/Sources/CapgoWatchPlugin/CapgoWatchPlugin.swift) and [CapgoWatchPlugin.java](https://github.com/Cap-go/capacitor-watch/blob/main/android/src/main/java/app/capgo/capacitor/watch/CapgoWatchPlugin.java).

| Capability | iOS (Apple Watch) | Android (Wear OS) | Web |
| --- | --- | --- | --- |
| `sendMessage` | Yes. Requires activated session and `isReachable`. | Yes. Sends on `/capgo/message` to connected nodes. Rejects if no Wear OS node is connected. | No |
| `updateApplicationContext` | Yes. Latest value only via WatchConnectivity. | Yes. DataItem at `/capgo/context` with JSON in `payload`. | No |
| `transferUserInfo` | Yes. Queued user-info transfer. | Yes. DataItem at `/capgo/userinfo/{uuid}` with JSON in `payload`. | No |
| `replyToMessage` | Yes. After `messageReceivedWithReply`. | Yes. Sends on `/capgo/reply/{callbackId}` to the watch node (5 minute pending TTL). | No |
| `getInfo` | Yes. WatchConnectivity pairing and reachability. | Yes. Connected nodes plus `capgo_watch` capability for watch app install detection. | Returns `isSupported: false` |
| `getPluginVersion` | Yes | Yes | Returns `{ version: "web" }` |
| `messageReceived` | Yes | Yes. Incoming `/capgo/message`. | No |
| `messageReceivedWithReply` | Yes | Yes. Incoming `/capgo/message/withreply`. | No |
| `applicationContextReceived` | Yes | Yes. Incoming `/capgo/context` DataItem. | No |
| `userInfoReceived` | Yes | Yes. Incoming `/capgo/userinfo/*` (phone deletes item after delivery). | No |
| `reachabilityChanged` | Yes | Not emitted on Android | No |
| `activationStateChanged` | Yes | Not emitted on Android | No |

## Core Capabilities

- `sendMessage` - Send an interactive message to the watch. The watch must be reachable for this to succeed. Use this for time-sensitive, interactive communication.
- `updateApplicationContext` - Update the application context shared with the watch. Only the latest context is kept - this overwrites any previous context. Use this for syncing app state that the watch needs to display.
- `transferUserInfo` - Transfer user info to the watch. Transfers are queued and delivered in order, even if the watch is not currently reachable. Use this for important data that must be delivered reliably.
- `replyToMessage` - Reply to a message from the watch that requested a reply. Use this in response to the messageReceivedWithReply event.
